## 图形界面（推荐）

双击桌面上的 **「AI 翻唱工坊」** 图标，或双击 `启动AI翻唱工坊.bat`，浏览器自动打开 <http://127.0.0.1:8765>。
关闭：界面右上角 **⏻ 退出**，或双击桌面「AI 翻唱工坊（停止）」/ `停止AI翻唱工坊.bat`。
服务是**独立进程**，关掉浏览器、关掉 DSH 或终端都不会中断正在跑的任务。

三步互相独立——每一步都能自己上传文件、自己导出结果，不必从第 ① 步一路跑下来：

1. **① 分离** — 拖入整首歌，选分离模型 / batch / segment / overlap / 精度，点「开始分离」。
   出干声与伴奏两个播放器，各自可 `⬇ 导出`、`📂 文件夹`，也可一键“送去转换/合成”。
   已经有干声的人可以直接跳到第 ② 步把干声拖进去。
2. **② 转换** — 直接拖入任意纯人声（不必来自第 ① 步）；自动列出 RVCMAX 全部模型与索引。
   参数：pitch、index_rate、rms_mix_rate、protect、filter_radius、f0 算法、重采样、检索开关、精度。
   先用「生成试听」拿一段 8~30 秒的「原干声 / 转换后 / 混上伴奏」三条对比，满意再「转换整首」；
   整曲结果同样可导出、可送去合成。
3. **③ 合成** — 人声轨与伴奏轨都能直接用上一步的结果，也能上传现成文件；
   新增「共振峰 0.80~1.10」滑杆（`<1` 听感更低更沉、音高不变，用来修「音高是准的但整首偏高」）；
   调音量、格式（WAV/FLAC/MP3/M4A）、限幅器、成品名，输出可试听 / 下载 / 打开文件夹。

交互细节：
- 每个参数名后面的 **?** 点一下有小弹框，里面写了「它是什么 + 实测数字 + 什么时候该调」；
  改参数前建议先看一眼，能避开大部分无效调参（例如 index_rate、protect 都调不了音色亮度）。
- 任务有进度条、当前步骤、耗时和 **取消** 按钮；同一时间只跑一个重任务（会显示“排队中”），
  避免 6GB 显存被两个任务同时占满。
- 第 ② 步有两个预设：
  · **★ 默认 · 硬骨头 B（推荐）**：去和声 + `index_rate 0.50 / rms_mix_rate 0.30 / protect 0.40 /
    crepe / index_k 28 / pre_gain 10 / 单段 100s` + 混响 8% + MP3 320k。流行、快歌、和声多首选。
  · **预设 A · 抒情/气声（更像模型）**：只做分离 + `index_rate 0.60 / rms_mix_rate 0.20 / protect 0.47 /
    crepe / index_k 10 / pre_gain 18` + 混响 14% 2.2s。慢歌、耳语、轻唱、模型音色本身是卖点。
  两个预设都会自动打开「校正到原唱音色」并把三段 EQ 归零。
- 需要针对个别问题时在预设基础上微调（? 里有说明）：口胡/吐字不清 → 先试第①步切「去和声」，
  再把 `index_rate` 提到 0.65~0.75；高音破音、突然卡顿或重复音 → `protect` 到 0.5、`index_rate` 降到 0.4、
  `f0` 换 crepe；气声/尾音太糊 → `rms_mix_rate` 调到 0.3~0.4。
- 命令行启动同样可用：`./py311/python.exe tools/webui/app.py --port 8765 --open`（端口被占用会复用现有服务）。

> 说明：RVCMAX 里的 formant / block_time / threold / crossfade_time / 输入输出降噪
> 是**实时变声**专用参数，其离线 VC 内核没有实现，界面上以灰色区域展示、不可调。

## 一键运行（命令行）

```bash
cd /d/AI/RVCover

# 用 RVCMAX 里 10 号模型（Yukkuri），升/降调 0
./py311/python.exe tools/pipeline.py "D:/path/song.mp3" --model-id 10 --pitch 0

# 男声→女声 +12，女声→男声 -12；检索比例 0.6；人声压低 3dB
```

## 分步运行

```bash
# 1) 分离（BS-Roformer，CUDA，fp16；约 1.5~2x 实时）
./py311/python.exe tools/separate.py song.wav --outdir work/mysong/stems --fp16 --batch 2

# 2) 变声（必须用 rvc_runtime 里的 Python 3.9 + torch 2.0，py311 跑不了）
./rvc_runtime/python.exe tools/rvc_convert.py \
   --input work/mysong/stems/vocals.wav --output work/mysong/vocal_converted.wav \
   --model-dir rvc_models/10_Yukkuri --model Yukkuri.pth \
   --index rvc_models/10_Yukkuri/Yukkuri.index \
   --pitch 0 --index-rate 0.55 --protect 0.45 --f0-method rmvpe

# 3) 合轨
./py311/python.exe tools/mix.py --vocals work/mysong/vocal_converted.wav \
   --instrumental work/mysong/stems/instrumental.wav --output work/mysong/final.wav \
   --vocal-gain -3 --instrumental-gain 0
```

## 两个环境坑（已在脚本里处理）

1. **HTTPS 拦截**：本机所有 HTTPS 走 127.0.0.1:443 的透明代理，Python/requests
   不认它的根证书。`separate.py` 会自动生成并注入 `tmp/ca_bundle.pem`
   （certifi + Windows 根证书）。若证书更新，删掉该文件会重新生成。
2. **faiss 不认非 ASCII 路径**：模型目录名含中文，`.index` 会被 RVC 的 faiss
   读取失败（静默退化成不用索引）。`rvc_convert.py` 会自动把 `.index`
   复制到 `work\_indices\` 下的 ASCII 路径再加载。

## 模型/参数速查

- 分离模型**只留两个场景各一个**（2026-11-02 实测后收敛，见 `work/_sep_eval/bench.py`）：
  - 默认 **`model_bs_roformer_ep_317_sdr_12.9755.ckpt`（标准流行）**：pop 场景人声 SI-SDR 21.96 dB 最高，
    伴奏也最干净，日常都用它。
  - **`mel_band_roformer_kim_ft2_bleedless_unwa.ckpt`（重混响 / 效果器多）**：对空间尾巴压得最狠，
    湿声场景尾巴 -99 dB（BS 是 -18.2 dB），编曲很湿、和声/效果器堆很多的歌换这个。
  - 原来的「Kim 原版」已移到 `models/_unused/`；Karaoke 与 DeReverb 模型不进下拉，只作二次处理内部使用。
  6GB 显存够用，fp16 + batch 2，整首 4~5 分钟歌约 3 分钟。
- 「人声清理」**一个开关管两件事**（2026-11-02 合并，替换掉原来的「只留主唱」「去混响/回声」两个下拉）：
  - `只做分离`（默认，最快）：人声原样送进 RVC。和声留着反而更饱满，多数歌就选这个。
  - `去和声`（+30% 时间）：某首歌和声/双轨叠唱特别重、出现“重复字/口胡”时才用，气声会略薄。
  - `去混响 / 回声`（+60% 时间）：对干声再跑 `dereverb-echo_mel_band_roformer_sdr_13.4843_v2.ckpt`，
    拆成「直达声 `(dry)`」+「被剥掉的混响 `(No dry)`」。现场版、翻录、混响给得足的歌明显干净。
  - `两样都做`：最干净也最慢（约 +90%）。
- 「净化人声」**已下线**（2026-11-02）：`bleed_suppressor` 实测会过度削人声（掉 20 dB），
  UI 里不再提供，模型文件仍留在 `models/mdxc/` 里备用。
- 「伴奏保留混响」**已下线**：改为第①步新增的「混响参数」——直接显示第③步要用的四个值
  （混响量 / 时长 / 预延迟 / 高频衰减），改这里第③步同步，不用来回切页。
- RVC：用 RVCMAX 的 `User_Data\models\<N>\*.pth` + 同名 `.index`。
  变调经验：男声素材转女声 +12，女声转男声 -12，同性别 0（可不调）。
  `index_rate` 越高越像目标音色但可能有金属感；默认 0.60，吐字不清时提到 0.65~0.75，破音/重复时降到 0.4。
- `pre_gain`（输入增益）：送进 RVC 前先整体推响，转换完自动匹配回原响度。
  弱音、气声、和声层在小音量下 RVC 的特征提不准就会口胡，+12~+18dB 常有改善；
  推太狠会被峰值上限卡住（日志会打印实际推多少 dB，常见只有 +1~+3dB）。
- 火绒拦截：把 `D:\AI\RVCover` 加进「防护中心 → 信任区」，否则快捷方式可能被拦或被杀软误删。
- **拿时间换质量的两个滑杆**（已进默认预设，不用动）：
  - **单段推理时长**（默认 **100s**，内核原值 65s）：一次丢给模型的最长音频。不切段时强制切点更少，
    长句/连唱/换气不断——用户实测「气息超级稳定，而且没有很慢」，后又把默认从 90 提到 100。
    往上调耗时按平方级涨（150 秒音频：65s 用 20 秒、90s 约 35 秒、120s 要 56 秒），6GB 显存建议 ≤120；
    调小＝更快更省显存，代价是接缝变多。
  - **检索邻居数 index_k**（默认 **10**，内核原值 8）：每帧从音色库里取几个最近邻做加权平均。
    调大＝音色更平滑统一、更像同一把嗓子，调小＝更贴模型本色但容易抖；对速度几乎没影响。
  注意：两件东西都只影响 RVC 那一段，分离质量不归它们管；两者都进文件指纹。
  页面默认（预设 B）指纹 `611657`，预设 A 指纹 `aa792e`（更早的 `a70eb1` = 单段 90s 的老默认，`4f046a` = 加滑杆之前的老预设）。

## 合成页：人声混响 / EQ / 母带匹配

第③步有「人声混响」（0~80%）、「混响时长」（0.3~6s）、「预延迟」（0~100ms）、「高频衰减」（2~16kHz），默认关。

### 三段 EQ（治“比原唱亮/闷”）

- **亮度 EQ**（`--eq-air`，8 kHz 以上高架）：比原唱亮就 −2~−4 dB，暗就 +2~+3 dB。
- **靠前度**（`--eq-presence`，2.2–4.2 kHz 钟形）：被伴奏压住 +1~+3 dB，太冲就收。
- **厚度**（`--eq-body`，180 Hz 低架）：单薄 +2~3 dB，浑浊就减。
- 这三个值正是 PitchIn-Q `timbre_bright` / `timbre_dark` 诊断给出的 `stage: "mix"` 建议项。

### 母带匹配（Matchering，导出前最后一步）

勾上「对齐到原曲」后，成品会先混成 24bit wav，再用 [`matchering`] 2.0.6 以**原曲**为参考
做一遍响度/频响/整体平衡匹配，最后才转成你选的格式（`tools/master.py`，18 秒素材约 0.4 秒）。
它只做“加分”，不改分轨；成品变闷或变尖就把勾去掉。

它是**平行送出**：干声原样保留，只叠一层卷积混响尾巴，用来把干净的新人声粘回伴奏的空间里。
效果器重的歌 12~20% 常有明显帮助；加多了人声会糊、尾音拖沓。

> 2026-11-01 修：卷积原来用 `mode="same"`，会把整条湿信号往前挪 `(len(ir)-1)//2` 个采样——
> 1.8 秒的混响等于提前约 0.9 秒冒出来（听感是“混响抢在人声前面”）。现在是因果卷积
> （`mode="full"` 取前 N 个采样），混响只会在人声之后出现。

补空间现在只有一条路：**第③步的人声混响**（参数可在第①步提前填好）。
原来的「伴奏保留原唱混响」（回填 `(No dry)` 层）已下线——多数歌用不上，且和去混响耦合太深。

## 滑杆范围与手动输入

每个滑杆右边都有一个数字框，可以直接打字输入精确值（滑块量程不够用时用它）：

| 滑杆 | 范围 | 说明 |
|---|---|---|
| 音高 pitch | −24 ~ +24（整数） | 半音 |
| 检索比例 index_rate | 0 ~ 1（步进 0.01） | 常用 0.4~0.6 |
| 音量包络 rms_mix_rate | 0 ~ 1（步进 0.01） | 常用 0.2~0.5 |
| 保护 protect | 0 ~ 0.5 | 内核上限就是 0.5 |
| 滤波半径 filter_radius | 0 ~ 7（整数） | **内核真实上限**；这版内核里只对 harvest 生效（>2 时做 3 点中值滤波），rmvpe/crepe 下几乎没有作用 |
| 输入增益 pre_gain | 0 ~ 30 dB（步进 0.5） | 峰值接近满量程时推不动，改用「弱音提升」 |
| 弱音提升 auto_level | 关 / +6 / +12 | 抬弱段，不动响段 |
| 单段推理时长 max_segment | 20 ~ 240 s | 6GB 显存建议 ≤120，耗时近似平方增长 |
| 检索邻居数 index_k | 2 ~ 128 | 太大检索会变慢 |
| 人声混响 reverb | 0 ~ 80 % | 合成页 |
| 混响衰减 revDecay | 0.3 ~ 6.0 s | 合成页 |

## 两套预设（第②步右上角）

| | **★ 默认 · 硬骨头 B（页面默认）** | 预设 A · 抒情/气声 |
|---|---|---|
| 适用 | 流行、快歌、和声多、人声湿/散、吐字含糊 | 慢歌、耳语/弱混声、模型音色本身就是卖点、源录音很轻、长音颤音多 |
| 人声清理 | **去和声** | 只做分离（保气声） |
| index_rate | **0.50** | 0.60（更像模型） |
| index_k | **28** | 10 |
| rms_mix_rate | **0.30** | 0.20（更跟随原唱动态） |
| protect | **0.40** | 0.47（更保气声） |
| filter_radius | 7 | 7 |
| f0 | **crepe** | **crepe**（实测两算法亮度只差 0.01 半音，crepe 气声/滑音更连贯） |
| pre_gain | **10** | 18（源音量小、峰值有余量时真推得动） |
| 单段推理 | 100s | 100s |
| 音色对齐 | 开（EQ 归零） | 开（EQ 归零） |
| 混响 | 8% / 1.8s / 25ms / 7kHz | 14% / 2.2s / 30ms / 6.5kHz |
| 输出 | MP3 320k | MP3 320k |

2026-11-01 用户结论：预设 B 在**多个音源 × 多个模型**上试听普遍优于 A，因此页面默认值就是 B；
A 保留为「抒情路线」——只有上面那几种情况才值得切过去。2026-11-02 更新：A 的 f0 从 rmvpe 改回 crepe
（实测两者亮度无差，crepe 对气声更友好），并补上混响 14% 与 MP3 输出，两个预设都会打开音色对齐。

机制：
- **index 0.50**（比 A 低）：检索拉太狠会抹平咬字，降一点保住源素材的辅音；代价是更像原唱。
- **index_k 28**（内核原值 8）：检索比例降了音色容易抖，用大量邻居做平均把 timbre 稳住。
- **protect 0.40**：快歌里 /s/ /t/ 这类清辅音和气口最容易被“唱化”。
- **rms_mix_rate 0.30**：人声动态大的素材，包络别拉太平。
- **crepe**：气声/沙哑/断裂的音高更稳（rmvpe 这类素材容易八度跳）。**速度实测只慢约 8~30%**
  （20 秒片段、含约 10 秒模型加载：rmvpe 14.1s / crepe 15.3s），早前文档写的“慢 2~3 倍”不准确。
- **pre_gain 10**：源干声峰值常已接近满量程，推多少都会被削波卡住（实测某首写 +10 只真推了 1.5 dB），
  留 10 只是少一点削波风险；真需要救弱音用第②步的「弱音提升」。

- **2026-11-01 定版（湿伴奏）**：把「去混响/回声」+「伴奏保留原唱混响（1×）」设为默认。

**2026-11-01 折中硬骨头 B（已成为页面默认，指纹 `611657`）**：`pitch 0 / index 0.50 / rms 0.30 /

不是分离不干净、也不是 RVC 音高不稳。

## 音质问题排查（怎么做 A/B）

对比实验的临时素材已经清掉了，现在直接在界面里做最快：第 ② 步填「起点 + 时长」（8~30 秒），
点「生成试听」拿三段对比（原干声 / 转换后 / 混上伴奏），改一个参数再生成一次就有了。
同一段的两次产物的文件名 hash 不同，不会互相覆盖，可以来回听。

已有的客观结论：
- 三个分离模型（BS-Roformer / Kim / Kim 无串音）在同一首歌的 4 个问题窗口上，
  “第二条谐波序列”比例基本一致（1.7~2.8），没有哪个模型显著更纯
  → 大概率是原曲本身的双轨/和声，不是分离残留。
- RVC 三组参数在 f0 指标上差异小于测量误差，**必须靠耳朵判断**。
- 因此：怀疑某一段有问题时，用第 ② 步的「起点 + 时长」截那一段，套预设 A/B 各生成一次，
  再决定整首用哪套参数。
