# AI 翻唱工坊 · 使用手册

> 一条流水线：**分离 → 转换 → 混音导出**，全本地、零费用。本手册按界面顺序写，每个参数都带「实测结论」，方便直接照着调。
>
> 版本：2026-11-02 · 适用于 `D:\AI\RVCover`（仓库：`kilier18/ai-cover-studio`）

---

## 0. 30 秒开始

```bat
双击 D:\AI\RVCover\启动AI翻唱工坊.bat
```

浏览器打开 <http://127.0.0.1:8765>，然后：

1. **第 1 步**：拖入歌曲 → 选分离模型 → 点「开始分离」（默认自动去和声）
2. **第 2 步**：选 RVC 模型 → 点「★ 默认 · 硬骨头 B」→ 开始转换
3. **第 3 步**：转换完成后会自动跑诊断并填好 EQ / 混响 → 检查一遍 → 开始混音

一首 4 分钟的歌，全流程约 **6~10 分钟**（去和声时分离时间翻倍）。

| 环节 | 4 分钟歌耗时 |
|---|---|
| 分离（BS-Roformer，不去和声） | ≈ 2:30 |
| 分离（+ 去和声，多一次推理） | ≈ 5:00 |
| RVC 转换（crepe） | ≈ 70s |
| PitchIn-Q 诊断 | ≈ 30s |
| 混音 + 音色对齐 + Matchering + MP3 | ≈ 30s |

## 1. 第 1 步 · 分离人声/伴奏

### 1.1 分离模型（只有两个，按场景选）

| 选项 | 文件 | 什么时候用 | 实测（18s 混合素材） |
|---|---|---|---|
| **标准流行 · BS-Roformer**（默认） | `model_bs_roformer_ep_317_sdr_12.9755.ckpt` (610MB) | 正常编曲的流行/摇滚/电子 | 人声 SI-SDR **21.96**（最高），伴奏最干净，空间尾巴 -18 dB（会被切掉一部分残响） |
| **重混响/效果器多 · Kim 无串音** | `mel_band_roformer_kim_ft2_bleedless_unwa.ckpt` (871MB) | 混响很湿、延迟重、失真/滤波人声 | SI-SDR 21.65（相差 0.3），但把非人声成分压得最狠：**尾巴 -99 dB** |

其余模型（Karaoke / 去混响 / 净化）不进下拉，只在「去和声」「去混响」时由程序内部调用。

### 1.2 人声清理

| 选项 | 含义 | 耗时 | 选择建议 |
|---|---|---|---|
| **只做分离（最快）** | 只跑一次分离 | ×1 | 抒情、气声、耳语为主；模型音色本身是卖点 |
| **去和声（推荐 · 和声/双轨重时）**（默认） | 再跑一次 karaoke 模型，把和声/双轨单独剥掉 | ×2 | 绝大多数流行歌。**实测同一首 5:53：八度跳变 21 处 → 1 处，评分 79 → 88** |
| 去混响 | 再跑一次 dereverb 模型（1.6s IR 兜底） | ×2 | 录音湿、拖尾回声重 |
| 两样都做 | 两次额外推理 | ×3 | 又湿又满是和声。代价：气声会略薄 |

> 为什么必须去和声：和声/双轨被一起喂进 RVC 会互相"抢"音高，表现为**重复字、口胡、突然跳八度**——这是 RVC 最常见的问题，不是分离不干净。

### 1.3 混响参数（会直接写进第 3 步）

| 参数 | 范围 | 默认 | 说明 |
|---|---|---|---|
| 混响量 | 0~80 % | 8（诊断会按清理方式自动给） | 只加在转换后的人声上；12~20% 适合效果器重的歌 |
| 时长 | 0.3~6 s | 1.8 | 1.2 紧 / 1.8 自然 / 2.5+ 大厅 |
| 预延迟 | 0~100 ms | 25 | 湿声比干声晚进来多少；20~30ms 最像真实房间 |
| 高频衰减 | 2000~16000 Hz | 7000 | 越低尾巴越暗、越像老磁带 |

其余分离参数一般不用动：`batch`（6GB 显卡用 2，爆显存就 1）、`segment=256`、`overlap=0.25`、`fp16`。

## 2. 第 2 步 · RVC 转换

### 2.1 导入模型

把 `<名字>.pth` + 同名 `.index`（可选）+ 头像拖进窗口，或点「⬆ 导入模型」，程序会在 `D:\AI\RVCover\rvc_models\<名字>\` 下建好目录。已有的模型库还会扫描 `D:\RVC模型\` 和 RVCMAX 的只读目录。

### 2.2 参数总表（含实测结论）

| 参数 | 范围/默认 | 作用 | 实测结论 |
|---|---|---|---|
| 音高 pitch | −24~+24 半音 / **0** | 整体升降调 | 同性别 0；男唱女 +12、女唱男 −12。**成品"听着偏高"别动这里**——实测中位偏差仅 +1.6 音分，先看音色对齐 |
| index_rate | 0~1 / **0.50** | 检索强度，越高越贴目标音色 | 0.2/0.5/0.8 的质心只差 0.2 半音 → **调不了亮度**；>0.8 金属感、齿音发毛 |
| rms_mix_rate | 0~1 / **0.30** | 0 跟随原唱起伏，1 用模型自身能量 | 0 与 1 亮度差 0.1 半音（可忽略）；想更平稳就调大 |
| protect | 0~0.5 / **0.40** | 保护气声/清辅音、防破音 | 0.2 与 0.45 质心完全相同（1759 Hz），不是亮度旋钮 |
| filter_radius | 0~7 / **7**（预设里给 7） | 音高曲线中值滤波 | 当前内核只对 harvest 生效；0 与 7 质心差 0.03 半音 |
| f0 算法 | crepe / **crepe** | 音高提取 | crepe 对气声/滑音/颤音最连贯，但 f0 提取慢约 2 倍；rmvpe 快、八度跳变最少；**两者亮度差 0.01 半音** |
| index_k | 2~128 / **28** | 每帧取多少个近邻 | 大 → 更平滑统一；小 → 更贴模型本人、细节多但易抖。对速度影响小 |
| pre_gain | 0~30 dB / **10** | 送进模型前推响 | 正常母带 0/3/6/10 无差别（转换后会还原响度）；**只有源干声 < −30 dBFS 才需要加**（实测 91 vs 85 分） |
| 单段时长 | 20~240 s / **100** | 每次推理的音频长度 | 65s 是内核原值；100s 长句更连贯；耗时近平方增长，6GB 显存别超 120 |
| 精度 | fp16 / **fp16** | 半精度 | 出现细碎电流声再切 fp32（显存翻倍） |
| 输出采样率 | 跟随模型 / **0** | 重采样 | 40k 模型出 40k，混音时自动升 44.1k |

### 2.3 两个预设

| | 预设 A · 抒情/气声 | ★ 预设 B · 硬骨头（默认） |
|---|---|---|
| 人声清理 | 只做分离（保气声） | 去和声 |
| index_rate | 0.60（更像模型本人） | 0.50 |
| rms_mix_rate | 0.20（更贴身） | 0.30 |
| protect | 0.47（护气声） | 0.40 |
| f0 | crepe | crepe |
| index_k | 10（细节多） | 28（平滑） |
| pre_gain | 18（救轻唱） | 10 |
| 混响 | 14% / 2.2s / 30ms / 6500Hz | 8% / 1.8s / 25ms / 7000Hz |
| 音色对齐 | 开（EQ 归零） | 开（EQ 归零） |
| 输出 | MP3 320k | MP3 320k |

**A 什么时候比 B 好**：慢歌、耳语/弱混声、模型的音色本身就是卖点、源录音很轻、长音颤音多。
**B 什么时候更稳**：流行快歌、和声多、吐字含糊、混响重的编曲。

## 3. 第 3 步 · 混音与导出

### 3.1 四个处理块（按信号顺序）

0. **共振峰 `0.80 ~ 1.10`**（默认 1.00 = 不动）
   整条人声的"声道长度"。`<1` 声道变长、听感更低更沉，**音高一个半音都不动**；`>1` 更年轻更薄。
   用来解决「音高明明是准的，但整首听着偏高/偏低」——那是模型自带的共振峰差异，不是跑调。
   实测古明地恋 × 少女期の終わりに：F2 2760 Hz vs 原唱 2293 Hz（+3.2 半音），乘以 **0.92** 后回到 +0.27 半音。
   建议顺序：先听原样 → 觉得偏高就 0.94 → 0.92 → 0.90，每次 2% 地降，直到"听着对了"；一次降太多会显得闷、像换了一个人。


1. **音色对齐 `校正到原唱音色`**（默认开）
   按原唱干声的长时频谱，把这条人声的频带整体校准。实测 4 个模型 −6.6 ~ +0.7 半音的偏差全部拉回 **±0.5 半音**，谐波/音高不动，所以不会跑调。
   *为什么需要它*：RVC 改的是音色，模型的"声道长度"和原唱不同，听感就会"整体偏高/偏低"——哪怕音高完全准。
2. **EQ**：`亮度(8kHz 高架)` / `靠前度(3kHz 峰)` / `厚度(180Hz 低架)`，±6 dB。
   开着音色对齐时诊断会把 EQ 填 0（两者都做等于调两次），只有关掉对齐才手调：**1 dB ≈ 1.7 个半音质心**。
3. **母带匹配 Matchering**（默认开）
   以原曲为参考，对齐响度/频响/整体平衡，相当于"和原曲一样响、一样亮、一样厚"。实测 18s 素材 **0.41 秒**。成品变闷/变尖就关掉。

### 3.2 其它

- **人声/伴奏电平**：人声比伴奏高 1~2 dB 最清楚；伴奏太吵 −1~−3 dB。
- **软限幅**：默认开，防两轨相加削波；关掉更通透但峰值可能 >1.0。
- **格式**：默认 **MP3 320k**；WAV 无损（约 10 倍体积）；FLAC 折中。
- **试听片段**：先跑 20 秒预览，满意再跑全曲。

## 4. 诊断（PitchIn-Q）

### 4.1 什么时候跑

- 转换完成后**自动**跑一次（90 秒上限），结果显示在第 3 步按钮旁；
- 也可第 3 步点「诊断」手动重跑；
- 诊断只读不写，不会改你的文件。

### 4.2 报告怎么读

```
诊断：质心 2530 → 1729 Hz（-6.6 半音 · 偏暗）→ 已填 eq_air 2.5dB / eq_presence 1.2dB
```

- **评分 0~100**：按「每分钟缺陷密度」扣分，长歌不会被缺陷总数拖垮（100 分制，88 分以上基本听不出问题）。
- **缺陷类型**：`offset`（错位 >60ms）、`pitch_off`（音准偏 >60 音分）、`pitch_jump`（八度跳变）、`doubled_syllable`（多出来的字）、`dropped_syllable`（漏字）、`level_jump`（音量跳）、`harsh`（齿音/发亮）、`over_smooth`（颤音被抹平）、`wobble`（抖）、`timbre_bright` / `timbre_dark`（音色偏亮/偏暗）。
- **参数方案**带着 `stage`：`rvc` / `mix` / `separate`，告诉你该去第几步改。

### 4.3 自动填参规则

| 诊断结论 | 自动动作 |
|---|---|
| 音色偏暗/偏亮 | 开了音色对齐 → EQ 填 0（交给对齐）；没开 → 填 `eq_air` ±2.5 dB、`eq_presence` ±1.2 dB |
| 第 1 步选了清理方式 | 自动给混响起始值：只分离 6% / 去和声 8% / 去混响 12% / 两样 14% |
| 音准系统性偏移 | 建议改 pitch（只在偏差 >60 音分时出现，常见于模型音域不匹配） |
| 亮度差 | 建议换模型或开音色对齐（**不改 index_rate/protect**，实测无效） |

### 4.4 并发规则

- 默认 `auto`：显存空闲（≥ 模型需求 + 900 MB）时**与 RVC 同时跑**，否则排队等锁；
- 显存不足时会提示「显存忙：显存被 xxx 占用」；
- 诊断模型用完立即卸载（`torch.cuda.empty_cache()`）。

## 5. 音色亮度问题：完整处置表

RVC 输出的"音色亮度"由模型决定，参数改不动。按偏差大小选手段：

| 偏差 | 处置 |
|---|---|
| ≤ 1.5 半音 | 不用管 |
| 1.5 ~ 3 半音 | 开「校正到原唱音色」（首选，实测落到 ±0.5） |
| 3 ~ 6 半音 | 同上；若仍不理想，EQ `亮度` 再补 ±1~2 dB |
| > 6 半音 | 换一个音色更接近的模型；EQ 只能救回来一半，且会损失通透度 |

> 参考数字：古明地恋模型在这个原唱上 −6.6 半音（偏暗），音色对齐后 −0.5 半音。

### 5.1 「音高听着偏高」——共振峰，不是音高

RVC 输出的音高通常完全准（实测中位偏差 +1.6 音分 = 0.016 个半音），但模型自带的**共振峰**（声道长度）
可能与原唱差 10~20%，人耳会把这读成「整首高了一点」。判定与处置：

| 现象 | 判定 | 处置 |
|---|---|---|
| 原唱与成品同调，但成品"飘在上面" | 共振峰偏高 | 第 3 步「共振峰」调到 0.92 左右 |
| 成品显得"闷、像换了个人" | 降过头 | 往 1.00 回调，或改走「音色对齐」 |
| 真的整体高了半个音/一个音 | 音高问题（少见） | 第 2 步 pitch −1 / −2，再用诊断确认音准分 |

实测数据（同一段 60 秒）：

| | F2 共振峰 | 相对原唱 | 音高偏差 |
|---|---|---|---|
| 原唱干声 | 2293 Hz | — | — |
| 模型输出 | 2760 Hz | **+3.2 半音** | +1.6 音分 |
| 共振峰 ×0.92 | 2329 Hz | +0.27 半音 | +1.6 音分（不变） |
| 共振峰 ×0.88 | 2260 Hz | −0.25 半音 | +1.6 音分（不变） |

> 实现：`tools/formant.py` 按帧做 LPC 包络沿频率轴缩放 + 保持帧能量（防止"抽气"式电平跳变），
> 60 秒素材约 2.3 秒。命令行 `tools/formant.py --input conv.wav --output conv_fm.wav --factor 0.92`，
> 或直接 `tools/mix.py --formant 0.92`。

**取值手感**：0.92 是「略降」，0.88 是「明显降」，0.84 以下容易听出「捏着嗓子/发闷」的加工痕迹；
往 1 以上的方向抬（1.03~1.10）会让声音更薄更飘，一般不建议。

**按模型记住初值**：每个模型第一次调好共振峰后，出片时会把该值记进 `work/_ui_prefs.json`；
下次在界面里选中同一个模型（第②步的模型下拉），第③步滑杆会自动回到这个值，标签显示 `0.88 ·记忆`。
换模型不会互相覆盖。想清掉记忆就删掉 `work/_ui_prefs.json`。

**为什么不做「自动测量共振峰」**：试过三种估计法（倒谱平滑后的长时平均谱做频轴拟合、LPC 极点取 F2、
包络找峰），在已知缩放比例的四段样本上（应恢复 1.20 / 1.09 / 1.03 / 0.98）全部失败——倒谱法的残差
始终贴 0（等于不做），峰比法给 1.05 / 1.04 / 1.03 / 1.02，相关法一律落在 1.00~1.03。也就是说
这些统计量测不出真实的共振峰差异，硬接上去只会给出一个看似聪明、实际错的值，所以这里选择
「你调好一次，就按模型记住」。

**渲染耗时对照（5 分 53 秒的整首歌，RTX 4050 Laptop）**：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 分离（BS-Roformer fp16，只做分离） | 约 3 分 50 秒 | 全程占 GPU |
| 分离 + 去和声 | 约 5 分钟 | 第二遍 Karaoke 模型 |
| RVC 转换（crepe / 100s 分段） | 约 70 秒 | |
| 诊断（PitchIn-Q，CPU） | 约 30 秒 | 不占显存 |
| 混音整链（共振峰 + 音色对齐 + EQ + 混响 + Matchering） | **约 33 秒** | 加速前约 60 秒 |

加速点：`tools/timbre.py` 的 tilt 搜索改成谱域解析式后，音色对齐从 4.4 秒/60 秒降到 1.4 秒/60 秒
（结果完全一致：同样选 +0.0 dB/oct，质心同样落到 3060 Hz）；`RVC_FORMANT_FAST=1`
再把这 60 秒的共振峰从 2.3 秒压到 0.2 秒，代价是共振峰估算与默认实现有约 0.1 半音级差异
（默认不开，怕动了你验证过的 0.88）。

## 7. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 网页 400 Bad Request，curl 也一样 | 本机 HTTP 代理把 127.0.0.1 的请求改写成绝对 URI。用 `curl --noproxy '*'`，或在 Python 里 `urllib.request.ProxyHandler({})` |
| 「显存忙：显存被 xxx 占用」 | 另一个任务占着 GPU。等它跑完，或删 `work\.gpu.lock`（确认没有进程在跑） |
| 转换报 CUDA out of memory | `batch` 降到 1、`单段时长` 降到 65、`精度` 用 fp16 |
| 出现重复字/口胡 | ①第 1 步开「去和声」；②`单段时长` 提到 100；③`protect` 提到 0.45 |
| 高音断裂/破音 | `protect` 提到 0.45~0.5，`index_rate` 降到 0.4 |
| 齿音刺、发亮 | 先看诊断；开了音色对齐仍亮就 `EQ 亮度` −1~−2 dB |
| 成品比原曲闷 | 关「母带匹配 Matchering」看是否它造成的；或 `EQ 亮度` +1~2 dB |
| 分离报找不到索引 / faiss 错误 | 索引路径含非 ASCII 字符，工具会复制到 `work\_indices\` 再读；还报错就把 `.index` 改名成英文 |
| 中文乱码 | 所有脚本已 `reconfigure(encoding="utf-8")`；`.bat` 必须 CRLF |
| 启动后端口被占 | `netstat -ano | findstr 8765`，kill 掉旧进程再启动 |

## 9. 参数改动原则（踩过的坑）

1. **亮度/音色问题只走「换模型 / 音色对齐 / EQ」三条路**，改 index_rate、protect、filter_radius、rms_mix_rate 都无效（实测 <0.2 半音）。
2. **pre_gain 不是音质旋钮**：转换后会还原响度，正常母带调它没意义；只对 < −30 dBFS 的轻干声有效。
3. **f0 算法不影响亮度**，影响的是音高轨迹连续性（crepe 顺、rmvpe 快且少八度跳）。
4. **去和声的收益远大于去混响**，绝大多数歌只需要开去和声。
5. 诊断的 `mean_cents` 已改成取中位数，避免八度错帧把整首判成"偏高 59 音分"。
