和参数调优有关的实测结论，看 [PARAMETERS.md](PARAMETERS.md)。

## 一、环境与运行

### 1. 本机所有 HTTP 请求 400 Bad Request

**现象**：`curl http://127.0.0.1:8765/api/separate` 返回 400，浏览器里却正常。
**原因**：本机代理（环境变量 `HTTP_PROXY` 指向 127.0.0.1:443）会把**发往 127.0.0.1 的请求也改写成绝对 URI**，Flask 不认这种请求行。
**处理**：脚本里一律 `curl --noproxy '*'`；Python 里 `urllib.request.build_opener(urllib.request.ProxyHandler({}))`。别再怀疑路由或跨域。

### 2. 控制台中文乱码

**现象**：`print("已完成")` 输出 ``，日志文件也乱。
**原因**：Windows 控制台默认 GBK，Python 按 GBK 编码输出。
**处理**：每个入口脚本第一行 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`，`.bat` 里加 `chcp 65001 >nul`。

### 3. `.bat` 用 LF 换行会「执行到一半就断」

**现象**：双击 bat 只跑了前几行，或者报 `'xxx' 不是内部或外部命令`。
**原因**：cmd 需要 CRLF。
**处理**：用 Python 写文件时 `open(p, "w", newline="\r\n")`，或写完 `unix2dos`。

### 4. Python 3.11 里 f-string 不能含反斜杠

**现象**：`SyntaxError: f-string expression part cannot include a backslash`。
**原因**：3.11 之前（含 3.11）不允许。
**处理**：先算到变量再插值：`p = str(path).replace("\\", "/")` → `f"{p}"`。

### 5. faiss 打不开含中文/日文的索引路径

**现象**：RVC 转换报索引加载失败，路径里带「芙兰朵露」「結月そら」。
**原因**：faiss 的 C++ 层用非 UTF-8 编码打开文件。
**处理**：复制索引到 `work/_indices/<stem>_<sha1前8位>.index`（纯 ASCII）再读。已在 `tools/rvc_convert.py` 里自动做。

### 6. 反斜杠被转义吃掉，路径静默变样

**现象**：写进配置文件/命令行的 `D:\AI\work` 变成 `D:AIwork`，或者 `\b` `\f` 变成退格/换页。
**原因**：Python 字符串、JS 字符串、heredoc 三层转义叠在一起。
**处理**：本项目内部**一律用正斜杠**（Windows 也认）；确实要反斜杠就 `r"..."` 或 `"\\"`。JS 里切路径用 `v.split(String.fromCharCode(92))`，比正则可靠（曾两次因 `/[\ /]/` 写坏导致 key 全错）。

### 7. 第一次调用要等 50 秒

**现象**：服务刚启动，第一次分离/转换前先卡 40–60 秒。
**原因**：`import torch, librosa, soundfile` 冷态 **53.3 s**，热态 1.9 s；再叠加模型文件首次读盘（杀毒扫描）。
**处理**：`tools/preheat.py` 顺序读模型文件（5.7 GB，热态 2.6 s），服务启动后自动跑一次；界面上也有「🔥 预热」。

### 8. 别按进程名杀进程

**现象**：`taskkill /IM pythonw.exe` 会把同机的其它服务（舞台服务器、桌宠）一起杀掉。
**处理**：按命令行/PID 精确匹配：`Get-CimInstance Win32_Process | Where CommandLine -like '*webui/app.py*'`，再 `taskkill //PID <pid> //F`。

## 二、音频处理

### 9. 「重复字 / 口胡」的主要原因是和声，不是分离不干净

**现象**：总觉得是分离模型不行，反复换模型没改善。
**原因**：原曲里主唱 + 和声/双轨叠唱，RVC 把两条人声都当主唱变声，才会出来叠字。
**处理**：第 1 步开「去和声」。实测同一段 60 s：普通分离 9 处八度跳 → 去和声后 **0 处**；全曲 21 → 1。

### 10. 分离模型不能只靠耳朵选

**现象**：A/B 听着都还行，选来选去没结论。
**处理**：用可量化指标——SI-SDR（对人声）、尾巴能量（对伴奏混响残留）、谱质心（音色偏移）。
实测：干净流行 BS 21.96 > Kim 21.65 > Kim 原版 21.48 > Karaoke 21.16；
重混响场景 BS 尾巴 −18.2 dB，而 Kim 系列 **−99.0 dB**（几乎无残留）→ 所以重混响选 Kim。

### 11. RVC 那四个参数**调不了音色亮度**

**现象**：觉得成品比原唱亮/暗，想靠 `index_rate`、`protect` 调。
**实测**：同一段 20 s 干声（源 2530 Hz），单参数各跑一次：
`index_rate` 0.2/0.5/0.8 → 1751/1755/1730 Hz；`protect` 0.2/0.45 → 1759/1759；`filter_radius` 0/7 → 1760/1758；`rms_mix_rate` 0/1 → 1763/1749。
**全部差 < 0.2 半音，等于调不动。**
**处理**：亮度只能靠 ① 换音色更接近的模型 ② 共振峰滑杆 ③ 音色对齐 ④ EQ。诊断里的建议已按这个改。

### 12. 音色对齐的参考比成品短，会把成品尾巴截掉（v1.0 修）

**现象**：导出偶发 `ValueError: operands could not be broadcast together with shapes (12779298,2) (12780768,2)`。
**原因**：`match_timbre` 里 `n = min(len(y), len(ref)); y, ref = y[:n], ref[:n]` 为了做统计把成品也截了；参考比成品短 1470 采样（约 33 ms，40 kHz→44.1 kHz 取整差）→ 和伴奏差 33 ms。
**处理**：参考只用于统计，输出严格保持输入长度；`mix.py` 在每个处理步骤后、相加前都再对齐一次。这类「差几十毫秒」在分离/转换间很常见，**不能假设两个 wav 等长**。

### 13. 一次性频谱匹配会过冲，要闭环

**现象**：用平均谱比（LTAS）一次性乘上去，质心从 +0.28 半音冲到了 +2.8。
**原因**：增益作用于谱包络后，质心的响应不是线性的。
**处理**：闭环搜索——固定增益，在倾斜网格（−3…+3 dB/oct，13 个候选）里挑，命中 ±0.4 半音即停；统计只做一次 STFT，最终只做一次 iSTFT。

### 14. 音色「像不像」不能只看一个指标

**现象**：LSD（对数谱距离）降了，但听感人声变闷。
**处理**：同时看三个——质心（亮度）、LSD（谱形）、八度跳/音准（pitchinq）；任一指标单独好看都可能是假象。

### 15. 共振峰的自动估计不可行（试过三种，全失败）

**现象**：想让程序自动算「这首歌该用 0.88 还是 0.92」。
**试过**：倒谱平滑 LTAS 频轴拟合、LPC 极点 F2、包络找峰。在已知真值（应恢复 1.20 / 1.09 / 1.03 / 0.98）的样本上分别给出 0.915/0.935/0.935/0.935 和 1.05/1.04/1.03/1.02 —— 测不出真实差异。
**处理**：不做自动测量，改成「按模型记住用户上次的选择」（`work/_ui_prefs.json`，标签 `·记忆`）。

## 三、诊断（PitchIn-Q）

### 16. 音准均值会被八度错帧拽飞

**现象**：报告说平均偏高 +59 音分、建议 `pitch −1`，但试听明显没这么偏。
**原因**：几十帧八度误判（+1200 音分）就能把 `nanmean` 拉走。
**处理**：只在 **±600 音分**内取**中位数**，`big` 掩码也用同一核心集合；实测中位 **+1.6 音分**。

### 17. 长歌的「缺陷数」评分不合理

**现象**：6 分钟的歌有 20 个缺陷就 0 分，3 分钟的歌 15 个缺陷却 60 分。
**处理**：改成缺陷密度 `score = 100 − 每分钟缺陷数 × 0.33`。

### 18. 3B 视觉模型不能用来量像素

**现象**：让它圈出「尾巴附近的蓝色方块」并给坐标，它回整图尺寸。
**处理**：视觉模型只用来**定性描述**，量测交给脚本（连通域、颜色聚类、低方差平坦区）。

## 四、服务与并发

### 19. 显存互斥必须跨进程

**现象**：网页端在跑转换时，命令行又起一个诊断 → CUDA OOM。
**原因**：进程内 `threading.Semaphore` 管不到别的进程。
**处理**：`tools/gpulock.py` 文件锁（`work/.gpu.lock` + owner.json，记录 pid/since，30 分钟陈旧清理，`GPULOCK_HELD=1` 让子进程重入）。`rvc_convert` / `webui.run_job` / `pitchinq --backend model` 三方都接同一把锁。

### 20. 每步都是新子进程，别指望进程内缓存

**现象**：明明上一步刚加载过模型，下一步还是要等。
**原因**：`webui/app.py` 每步 `subprocess.Popen([sys.executable, tools/xxx.py])`。
**处理**：接受固定开销，用 `preheat.py` 把**文件**读热（内存缓存跨进程有效）；真要零加载得常驻模型服务，暂未做。

### 21. 试听地址不要把缓存参数拼进路径

**现象**：导出后播放器 404，看着像「导出失败」。
**原因**：`setMedia(el, rel + '?t=' + Date.now())` 把查询串拼进了文件路径，`/media?p=xxx.mp3?t=…` → 文件不存在。
**处理**：路径与查询串分开，`&t=` 追加；所有 `/media` 调用点统一走一个 `setMedia(el, path, noCache)`。

## 五、其他

- **日志先落盘再说话**：`work/_jobs/<任务id>.log`，失败信息带最后两行 stderr。排障时间从「猜」变成「看」。
- **可选步骤要能失败**：母带匹配、预热这类「锦上添花」的步骤标 `optional`，挂了只记 `warnings`，别让整个任务红掉。
- **改完全局正则先自检**：一次把 `replace(/\\/g,'/')` 写成 `replace(/\/g,'/')`，整页 JS 挂掉（`SyntaxError`），页面症状是「按钮全没反应」。改 JS 后用 `node --check` 或页面 evaluate 验一下。
