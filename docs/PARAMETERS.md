# 参数全表（每一项到底影响什么）

第②步界面上所有滑杆都在这里。**"内核支持"一列**决定这个参数在你的 RVC 版本上到底有没有用 ——
RVC 各家 fork 差异很大，改了没效果多半是内核没实现。

## 一、RVC 变声参数

| 参数 | 范围（界面） | 默认 | 作用 | 内核支持 |
|---|---|---|---|---|
| 变调 `pitch` | −24 ~ +24 | 0 | 升/降半音。男→女常 +12，女→男 −12，同性别 0 | ✅ 一定生效 |
| 检索比例 `index_rate` | 0 ~ 1（步进 0.01） | 0.50 | 用检索索引把音色往目标模型拉多少。高 = 更像模型、咬字可能糊；低 = 更保原唱咬字 | ✅ |
| 检索邻居 `index_k` | 2 ~ 128 | 28 | 每帧取多少个邻居做加权平均。高 = 更平滑统一、低 = 更贴模型本色；**对速度几乎无影响** | ⚠️ 需要内核有 `INDEX_K`（本项目补丁），原版硬编码 8 |
| 响度混合 `rms_mix_rate` | 0 ~ 1 | 0.30 | 输出响度包络跟随原唱的比例。0 = 完全用模型自己的动态，1 = 完全跟随原唱 | ✅ |
| 保护清辅音 `protect` | 0 ~ 0.5 | 0.40 | 保护清辅音/气声不被模型抹平。高 = 咬字清楚但可能带原唱气口；**内核上限 0.5** | ✅ |
| 滤波半径 `filter_radius` | 0 ~ 7 | 7 | 对 f0 做中值滤波去毛刺 | ⚠️ **只对 harvest 生效**（`pipeline.py` 里 `medfilt` 只在 harvest 分支），rmvpe/crepe 下无效 |
| 音高算法 `f0_method` | rmvpe / crepe / harvest / pm | crepe | 提取音高的算法。rmvpe 最稳最快、crepe 对湿人声更稳、harvest 慢且需要 filter_radius | ✅ 四选一（**没有 fcpe**，那是实时版的） |
| 输入增益 `pre_gain` | 0 ~ 30 dB | 10 | 送进 RVC 前把干声推响，输出再压回原始响度 | ✅ 但**常被峰值限幅**：源峰值接近满量程时 +18 实际只推得动 2~3 dB |
| 弱音提升 `auto_level` | 0 / 6 / 12 | 0 | 只把弱帧抬起来，上限 N dB，峰值封顶 0.98 | ✅ |
| 单段推理时长 `max_segment` | 20 ~ 240 s | 100 | 长音频多久切一刀。大 = 段间更连贯、气口更自然，但耗时按平方增长（150 s 音频：65 s→20 秒、90 s→35 秒、120 s→56 秒） | ⚠️ 需要本项目补丁（`x_max/x_center/x_query`），原版固定 65 s |
| 重采样 `resample_sr` | 0 或任意 | 跟随模型 | 强制输出采样率；0 = 用模型自带（32k/40k/48k） | ✅ |
| 半精度 `fp16` | 开/关 | 开 | 显存减半、速度略快；老显卡有 NaN 风险时关 | ✅ |
| 索引模式 `index_mode` | 自动/强制/关闭 | 自动 | 是否加载 `.index`；目录里有多个索引时手动指定 | ✅ |

### 内置不支持（界面里灰色，仅作对照）

| 参数 | 为什么不能用 |
|---|---|
| `formant`（共振峰） | 离线 `vc_single()` 没有这个入参，实时变声才用 |
| `block_time` | 实时分块参数，离线一次性推理 |
| `extra_time`（额外推理时长） | 实时版每块推理的额外上下文窗口，离线不存在 |
| `threold` / `crossfade` | 实时串流拼接用 |
| `noise_reduce` / DeepFilterNet | 这版内核的离线路径没接 |

> 这些在界面上保留只是为了让你知道"整合包里看到过这些参数"——它们不会生效，别在这里找问题。

## 四、两套预设的来历（怎么调出来的）

**默认 · 硬骨头 B**：`index 0.50 / index_k 28 / rms 0.30 / protect 0.40 / pre_gain 10 / crepe / 100 s`
在多个音源 × 多个模型上复测过，咬字最稳，是对的"通用默认值"。

**预设 A · 抒情/气声**：`index 0.60 / index_k 10 / rms 0.20 / protect 0.47 / pre_gain 18 / rmvpe`
每个值都对应一类场景：

- `index 0.60` —— 想要更像模型本身的音色（而不是原唱）
- `protect 0.47` —— 气声、耳语、尾音多
- `rms 0.20` —— 原唱动态特别大（忽强忽弱）
- `pre_gain 18` —— 原录音电平低、峰值还有余量（这时才真的推得动）

**调参方法**：第②步填「起始秒 + 时长」（10~20 秒足够），生成三段对比（原干声 / 转换后 / 混上伴奏），
A/B 听出来再应用到整首。**不要用 f0 指标判断音质**——跳音率、八度错误率和听感基本无关。

## 五、指纹（文件名里的 6 位 hash）

界面生成的每个产物都带参数指纹，例如 `vocals__m6__a70eb1.wav`。

- 指纹 = 所有影响结果的参数（模型的**绝对路径**、index_rate、protect、pre_gain、max_segment…）的 sha1 前 6 位。
- 同一组参数永远得到同一个指纹，方便"这版我听过，那个文件就是它"。
- **改参数会影响指纹**；只改界面文案、颜色不会。
- 类型敏感：`index_k=28`（int）和 `28.0`（float）会算出不同指纹 —— 改代码时保持一致。

## 六、想自己加一个参数？三步

1. `tools/rvc_convert.py`：加 argparse，并在调用 `vc_single(...)` 或改 `config.*` 的地方用上它；
2. `tools/webui/app.py`：`rvc_cmd()` 里拼进命令行，`tag_of()` 的 `payload` 里加上它（否则指纹不区分）；
3. `tools/webui/static/index.html`：加滑杆 + `params()` + `syncLabels()` + 预设复位。

改完跑一次 `python tools\check_env.py`，再用 20 秒片段试听。
